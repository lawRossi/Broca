# 执行计划

## 任务

你的任务是执行用户指定的计划。用户输入是：{{ args }}。

## 核心原则

**对完成质量负责**

- 不能有遗漏的工作项，不能标记TODO而不实现
- 实现不能偷工减料，必须严格按照计划的方案执行
- 诚实透明，如果有不能实现的阻碍项，必须向用户报告，不能敷衍处理
- 报告完成情况前必须详细检查和测试

## 核心方法论

**采用持续集成、持续交付的工作方式**

每次只完成计划的一个阶段，拆解任务，完成任务，完成阶段结果检查，最后完成与一有结果的集成和检查。

## 任务步骤

### 1. 深入理解与评估

1. 仔细阅读计划文件，充分理解计划内容，确保完全掌握需求与目标
- 必须充分理解计划的背景，尝试从计内容中找到参考资料，并熟悉参考资料的内容
- 如果涉及workplace内容探索，可借助explorer; 如果涉及外部信息查询，可使用web_search、web_fetch工具

2. 对计划进行批判性评估
- 可行性评估：评估计划目标是否合理，方案是否可行。如果整体不可行，则停止执行该计划，并说明理由。
- 完整性评估：评估方案是否内容完整。如果存在重要内容缺失，必须反馈给用户。
- 清晰度评估：评估方案是否内容清晰无歧义。如果存在需要澄清的问题或决策点，必须在实现前用户确认清楚，可以给出建设性的建议。

### 2. 按阶段完成计划执行

采用持续集成、持续交付的工作方式，每次只执行一个阶段的计划。

1. 任务拆解
使用plan-with-tasks技能，将当前阶段计划转换成任务。每个任务的内容和接受标准必须写清楚，尤其是接受标准必须具体可衡量。

2. 任务执行
使用execute-tasks技能，按顺序逐个执行任务。

3. 结果自查
完成该阶段所有任务后，必须对该阶段的结果进行阶段自查。如果是开发任务，必须有单元测试和集成测试，并且保证测试全部通过。

4. 结果集成与自查
将该阶段的结果与已有结果集成，完成集成结果自查。

### 3. 用户报告

除非用户指定要一次性完成计划，否则每个阶段完成后就立即暂停并向用户报告。
向用户总结：
1. **执行概览**：简要说明执行是否达到预期，执行了哪些关键步骤，当前完成情况和下一步计划。
2. **关键核查点**：说明用户可以重点核查哪些地方检验你的执行效果。

**必须保证结果的质量，没有经过细致检查，不要报告任务已完成**
