# 制定计划

用户的输入是：{{ args }}

## 任务

你的任务是根据用户的输入，进行深入的思考和推理，制定出一份**完整的计划文档**。

## ⚠️ 核心约束

**你只能制定计划并形成文档，绝对不能执行任何计划中的具体步骤。**
- 你不应该运行任何实际构建、修改、部署等操作
- 你不应该调用任何会改变系统状态或文件（除了写计划文档本身）的工具
- 你的唯一产出是一份计划文档（未指定格式时默认采用markdown）

## 任务步骤

### 1. 深入理解与思考

- 熟悉问题背景和现状。如果需要探索当前workspace，先分配任务让explorer给出概览和重点，你再针对性看重点；如果需要搜索信息，则使用web_search和web_fetch工具
- 分析用户的目标、需求和约束条件
- 思考可能的实现方案，评估各方案的权衡，关键决策点给出建设性建议，且必须使用ask_user工具和用户确认(一次一个问题，避免信息过载)
- 识别潜在的风险和挑战，并给出应对措施

### 2. 制定分层计划

将计划组织为清晰的层级结构：

#### 阶段 (Phase)
每个阶段是一个大的里程碑，按逻辑顺序排列。

#### 任务 (Task)
每个阶段下包含若干具体任务，每项任务应包含：
- **目标**：任务要达成什么
- **步骤**：具体的执行步骤
- **预期产出**：完成后会有什么成果

#### 依赖关系
明确任务之间的依赖关系和执行顺序。

### 3. 形成计划文档

将完整的计划写入 `plans/` 目录下的 Markdown 文件。

**文件命名规则**：根据用户输入的核心主题生成文件名，使用英文小写+连字符。例如：
- 用户想"做一个博客平台" → `plans/blog-platform-plan.md`
- 用户想"重构支付模块" → `plans/payment-module-refactor-plan.md`

**文档模板**：

```markdown
# {计划标题}

## 概述
- **目标**：{用户的核心目标}
- **背景**：{用户提供的背景信息}
- **约束条件**：{任何约束条件}

## 总体方案
{对整体方案的简要描述，包括技术选型、架构决策等}

## 执行计划

### Phase 1: {阶段名称}
**目标**：{本阶段目标}

#### Task 1.1: {任务名称}
- **目标**：{任务目标}
- **步骤**：
  1. {步骤1}
  2. {步骤2}
  3. ...
- **预期产出**：{产出描述}

#### Task 1.2: {任务名称}
...

### Phase 2: {阶段名称}
...

## 风险与应对
| 风险 | 影响 | 应对策略 |
|------|------|----------|
| ... | ... | ... |

## 未解决的问题
- {需要在执行前澄清的问题}
- {需要在执行中确认的决策点}
```

### 4. 向用户报告

计划文档生成后，向用户总结：
1. **计划概览**：简要说明计划包含几个阶段、多少任务
2. **关键决策**：列出计划中做出的关键决策
3. **下一步**：询问用户是否要执行该计划，或对计划进行调整
4. 提醒用户：如果要执行计划，请使用 `/execute-plan` 命令

**未经用户明确确认，绝对不能开始执行计划中的任何步骤。**
